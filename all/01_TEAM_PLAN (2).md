# AIRLOCK — План команды: кто что делает и как собирается цепочка

Часы считаются от момента старта работ (час 0). Тимлид записывает в чат реальное время для каждой контрольной точки C0–C6 исходя из настоящего дедлайна lablab (на странице 9 ноября 4:00 AM KT, «KT» уточнить). Заморозка функций (C5) — не позже чем за 8 часов до дедлайна.

## 1. Разделение зон ответственности

Почему так: каждая зона заканчивается чёткой границей API, поэтому работать можно параллельно с первого часа.

## 5. Правила, чтобы не было конфликтов

1. **Свои директории.** Коммит в чужую директорию — только через PR, который одобряет владелец.
2. **Ветки:** `main` защищена по смыслу (прямых пушей нет); рабочие ветки `alikhan/<тема>`, `bakhtiyar/<тема>`, `damir/<тема>`. PR маленькие (до ~300 строк), мерж по мере готовности, ребейз на `main` перед PR.
3. **Контракт:** меняется только по протоколу из `00_SHARED_CONTRACT.md` §11.
4. **Секреты:** никогда в git. `.env` — локально, на VM#1 — в файле, недоступном остальным. В песочницу секреты не попадают (проверяется тестом).
5. **Формат коммитов:** `area: что сделано` (например `runner: add canary files for ci profile`).
6. **Статус в общий чат** каждые 2 часа одним сообщением: `Сделано / Делаю сейчас / Блокирует меня (кто и что) / Нужно от других`.
7. **Блокировка:** если ждёшь чужой результат больше 30 минут — пишешь в чат, не переписываешь чужую часть. Тимлид перераспределяет.
8. **Определение «готово»** для PR: запускается локально, есть сценарий проверки в описании PR (команда `curl` или шаги в UI).
9. **Фича-флаг вместо долгих веток:** незавершённое прячется за env-флагом, но живёт в `main`.

## 6. Что режем при нехватке времени (по владельцам)

| Порядок | Что | Чья зона |
|---|---|---|
| 1 | `tier=burn` / throwaway VM → в видео показать записанный жизненный цикл VM (честная подпись) | Бахтияр + Алихан |
| 2 | History, Operator-экран, экспорт PDF | Дамир |
| 3 | Re-verify (оставить статичную Receipt) | Алихан |
| 4 | Профиль `future-date` (оставить `dev-laptop` и `ci`) | Бахтияр + Алихан |
| 5 | Ввод `zip` и `npm` (оставить `paste` и `npm`) | Алихан + Бахтияр |

**Не режутся никогда:** песочница с лимитами и canary (Бахтияр), агентный цикл на Vultr Inference и Verdict Engine (Алихан), Live Tripwire и отчёт Claim vs Behavior (Дамир), README и видео (Дамир).

## 8. Чек-лист тимлида на первые 3 часа (P0)

1. Регистрация Vultr с почтой, ранее не связанной с аккаунтом Vultr → верификация → Gift Code в Billing → проверить `$200.00 Remaining Credit`.
2. Создать VM#1 (Control Plane, 2 vCPU/4 GB) и VM#2 (Sandbox Host, 4 vCPU/8 GB), включить приватную сеть/VPC, настроить Firewall Group: VM#2:9000 принимает только IP VM#1; SSH — только IP команды.
3. Создать API-ключ Serverless Inference и проверить `GET https://api.vultrinference.com/v1/models`; записать выбранные модели для Planner и Explainer (по поддержке tool-calling/JSON и цене).
4. Создать отдельный ограниченный Vultr API-ключ (для fleet). Выдать только Бахтияру на dev и положить на VM#1.
5. Подтвердить в консоли, что токены Inference списываются из кредитов; включить уведомления о расходах в Billing.
6. Создать репозиторий, структуру из `00_SHARED_CONTRACT.md` §1, `CODEOWNERS`, `.env.example`; раздать доступы.
7. Раздать промпты (`PROMPT_*.md`), согласовать время контрольных точек C0–C6 с реальным дедлайном.
8. Уточнить в Discord lablab значение «KT» и обязательность on-site присутствия финалистов.
